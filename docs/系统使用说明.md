# MiniSQL 系统使用说明

适用版本：当前包含图形工作台的 MiniSQL 0.1.0。

更新日期：2026 年 9 月 10 日。

项目目录：`E:\zch_Projects\sql_project`。

本说明面向首次使用者和课程演示人员，介绍环境准备、图形界面、SQL 操作、事务、命令行、教学分析及常见问题。所有命令均在项目根目录执行。

## 1. 系统简介

MiniSQL 是一个教学用小型数据库系统，使用自研 SQL 编译器、执行引擎和页式存储完成数据操作。表结构和记录保存到本地文件，正常关闭并重新打开后仍可访问。

系统提供两种操作方式：

| 方式 | 适合的场景 | 启动入口 |
|---|---|---|
| 图形工作台 | 日常操作、观察查询结果、课程演示 | 双击 `start_gui.cmd` |
| 命令行 | 交互输入、执行 SQL 文件、自动化实验 | `python -m minisql` |

两种方式调用同一套数据库引擎。连接相同的数据库目录时，可以访问同一份已提交数据。

主要功能包括建表、插入、单表条件查询、删除记录、删除表、去重、限制返回行数、执行计划展示、事务提交与回滚，以及编译过程和缓存统计展示。

## 2. 环境准备与启动

### 2.1 运行要求

- Python 3.11 或更高版本。
- 图形界面需要可用的现代浏览器，例如 Chrome 或 Edge。
- 数据库目录需要有读写权限。
- 系统运行使用 Python 标准库；图形界面资源保存在本地，无需 Node.js 或联网。

安装开发依赖时可能需要联网，或者事先准备相应的离线安装包；这与系统日常运行是否联网无关。

### 2.2 推荐方式：双击启动

1. 打开项目文件夹 `E:\zch_Projects\sql_project`。
2. 双击 `start_gui.cmd`。
3. 等待浏览器自动打开工作台。
4. 顶部显示“已连接”后，即可输入和运行 SQL。

默认访问地址为 [http://127.0.0.1:8765](http://127.0.0.1:8765)。此地址仅在本地服务运行时可用。浏览器没有自动打开时，可手动输入该地址。

启动脚本优先使用项目内的 `.venv`；没有该环境时使用 Windows 的 `py -3`。脚本会直接加载项目源码，不要求提前安装 MiniSQL 包。保持启动窗口运行，关闭服务前先处理未提交事务。

### 2.3 首次配置 Python 环境

如果需要配置虚拟环境、使用命令行入口或运行测试，可执行：

```powershell
cd E:\zch_Projects\sql_project
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m minisql --help
```

已有可用的 `.venv` 时，不必重复创建。

### 2.4 手动启动与参数

```powershell
# 使用默认图形数据库目录 data/gui
.\.venv\Scripts\python.exe -m minisql.gui

# 使用指定数据库目录和端口
.\.venv\Scripts\python.exe -m minisql.gui --data-dir .\data\practice --port 8767

# 只启动服务，不自动打开浏览器
.\.venv\Scripts\python.exe -m minisql.gui --no-browser
```

| 参数 | 含义 | 默认值 |
|---|---|---|
| `--data-dir` | 数据库目录 | `data/gui` |
| `--port` | 本地服务端口；设为 0 时由系统分配空闲端口 | `8765` |
| `--no-browser` | 不自动打开浏览器 | 不启用 |

安装或重新安装包含 GUI 的项目后，也可使用 `.\.venv\Scripts\minisql-gui.exe` 启动。

## 3. 图形工作台操作

![MiniSQL 图形工作台](assets/gui-workbench.png)

### 3.1 页面区域

| 区域 | 用途 |
|---|---|
| 顶部连接信息 | 查看当前数据库名称和连接状态，打开“管理连接” |
| 左侧数据库结构 | 浏览表名、字段及类型，筛选表，刷新目录 |
| SQL 工作台 | 编辑和执行 SQL，查看结果与错误，操作事务 |
| 编译分析 | 查看 Token、AST、语义检查和优化前后计划 |
| 缓存统计 | 查看页缓存访问、命中、淘汰、写回和替换记录 |
| 使用帮助 | 查看界面操作提示和当前系统限制 |

### 3.2 连接、切换与断开数据库

点击右上角“管理连接”，输入数据库**目录**，例如：

```text
E:\zch_Projects\sql_project\data\practice
```

输入的是目录，不是 `minisql.db` 文件的路径。不存在的目录会被创建；相对路径以服务启动目录为基准。

切换连接前，建议先点击“提交”或“回滚”。如果仍有未提交事务，界面会询问是否回滚后切换；取消后仍保留原连接。断开连接同样会处理未提交事务。

**图形界面默认目录为 `data/gui`，命令行默认目录为 `data`。** 如果切换操作方式后看不到原来的表，先核对目录是否相同。

### 3.3 编辑与运行

- **运行全部**：执行编辑器中的全部 SQL，按顺序处理。
- **运行选中**：只执行选中的文本；选中的语句也需要完整并以分号结束。
- **Ctrl+Enter**：有选区时运行选中内容，没有选区时运行全部。
- **Tab**：在编辑器中插入两个空格。
- **加载示例**：将入门 SQL 填入编辑器，点击运行后才会执行。
- **浏览数据**：点击表下方的链接，直接查询并显示表数据，支持上一页/下一页翻页（每页 50 行）。

运行期间编辑器和运行按钮暂时禁用，等待结果后继续操作。页面没有自动重试写入请求。

### 3.4 打开与保存 SQL 文件

编辑器标题栏中的文件夹按钮用于打开 `.sql` 或文本文件，保存按钮将当前内容下载为 SQL 文件。

- 文件使用 UTF-8 编码，支持中文字符串和注释。
- 打开文件仅将内容放入编辑器，不自动执行。
- 打开文件的大小限制为 240 KB；服务单次请求体限制为 256 KB，包含 JSON 包装与转义开销。
- 保存的是 SQL 文本，不是查询结果或数据库备份。

较大的 SQL 文件可拆分为多个文件，或通过命令行文件模式运行。

### 3.5 查看结果与错误

成功批次按语句分别显示结果：查询显示列名和数据行，其他操作显示消息及影响行数。结果每页展示 50 行，翻页不会重新执行 SQL。

显示分页不会减少引擎生成结果集的内存占用。只需查看部分记录时，可在 SQL 中使用 `LIMIT`。

失败时显示错误阶段、错误码、原因和可用的源码位置。点击“定位到第 X 行，第 Y 列”可跳到编辑器中的相应位置。

## 4. 第一次实验：建表、插入与查询

先连接一个新的练习目录，例如 `data/manual-practice`。下列示例要求该目录中尚未存在 `student` 表。

将以下 SQL 粘贴到工作台，点击“运行全部”：

```sql
CREATE TABLE student(id INT, name VARCHAR, age INT);

INSERT INTO student(id, name, age) VALUES (1, 'Alice', 20);
INSERT INTO student(id, name, age) VALUES (2, 'Bob', 17);
INSERT INTO student(id, name, age) VALUES (3, '张三', 22);

SELECT id, name, age FROM student WHERE age > 18;
```

结果包含以下两条记录（未使用 ORDER BY 时不承诺固定顺序）：

| id | name | age |
|---|---|---|
| 1 | Alice | 20 |
| 3 | 张三 | 22 |

左侧也会出现 `student` 表及三个字段。再次执行整个示例会遇到同名表错误；已经建表后，只选中需要再次运行的查询即可。

以下第 5～7 节示例以本节数据为基础，可按顺序练习。

## 5. 查询与 SQL 基本规则

### 5.1 查询全部、指定字段与条件查询

```sql
SELECT * FROM student;
SELECT id, name FROM student WHERE age >= 18;
SELECT id, name FROM student WHERE age >= 18 AND age < 22;
SELECT id, name FROM student WHERE name = '张三';
```

查询条件支持比较运算 `=`、`!=`、`<>`、`<`、`<=`、`>`、`>=`，以及 `AND`、`OR`、`NOT`、括号和整数加减。WHERE 的最终结果必须是布尔值。

### 5.2 去重、排序与限制行数

```sql
SELECT DISTINCT age FROM student;
SELECT id, name FROM student ORDER BY age DESC;
SELECT id, name FROM student ORDER BY age DESC, id ASC;
SELECT id, name FROM student LIMIT 2;
SELECT id, name FROM student LIMIT 2 OFFSET 1;
SELECT DISTINCT age FROM student LIMIT 2;
```

DISTINCT 在选定字段上去重。ORDER BY 可多列排序，逐列可选 ASC（默认）或 DESC，排序列必须出现在投影列中。LIMIT 与 OFFSET 后必须是非负整数字面量；OFFSET 跳过前 N 行，只能跟在 LIMIT 之后。

### 5.3 查看执行计划

```sql
EXPLAIN SELECT id, name FROM student WHERE age > 10 + 8 AND 1 = 1;
EXPLAIN DELETE FROM student WHERE id = 3;
```

EXPLAIN 显示优化后的执行计划，不执行内部查询或删除。`EXPLAIN DELETE` 不会删除记录；表名、列名和类型仍会被检查。整个 EXPLAIN 语句末尾写一个分号即可。

### 5.4 数据类型与输入规则

| 项目 | 当前规则 |
|---|---|
| 表字段类型 | `INT`、`VARCHAR` |
| INT 范围 | 有符号 64 位整数：−9223372036854775808～9223372036854775807 |
| VARCHAR | 可保存中文字符串；建表写 `VARCHAR`，不写 `VARCHAR(n)` |
| 布尔值 | TRUE/FALSE 用于表达式，不支持 BOOL 表字段 |
| 表名、列名 | ASCII 字母或下划线开头，后续可含数字；大小写不敏感 |
| 字符串 | 单引号包围；字符串中的单引号写成两个连续单引号，例如 `'O''Brien'` |
| INSERT | 必须列出全部字段，不允许重复字段，可以调整列顺序；值顺序对应所列字段 |
| 语句结束 | 每条 SQL 以分号结束 |
| 注释 | 支持 `-- 行注释` 与非嵌套 `/* 块注释 */` |

一条 INSERT 插入一条记录；多条记录使用多条 INSERT。当前系统不会自动补齐缺少的字段，也不会把字符串自动转换为整数。

## 6. 删除记录与删除表

### 6.1 删除指定记录

```sql
DELETE FROM student WHERE id = 3;
SELECT * FROM student;
```

删除后剩余 Alice、Bob 两条记录，表结构仍然存在。`DELETE FROM student;` 会删除表内全部记录，因此要删除部分数据时应写明 WHERE 条件。

### 6.2 删除整张表

`DROP TABLE student;` 删除表结构和全部记录。自动提交后，该表不会因为重启程序而恢复。

如果只是练习删表，可以使用以下事务示例，最后回滚以恢复原表：

```sql
BEGIN;
DROP TABLE student;
ROLLBACK;
SELECT * FROM student;
```

不支持 `DROP TABLE IF EXISTS`。删除不存在的表会报错，系统目录表不能删除。

删除记录后，系统会回收页内空间用于后续插入，但数据库文件不一定立即缩小。

## 7. 事务：提交与回滚

### 7.1 自动提交

默认情况下，每条成功的 SQL 单独提交。一个批次中途报错时，后续语句停止执行，**此前成功自动提交的操作可能已经生效**。

失败批次不返回部分执行结果，不代表整批操作已经撤销。需要重新查询确认当前数据。

### 7.2 回滚一次修改

```sql
BEGIN;
DELETE FROM student WHERE id = 1;
SELECT * FROM student;
ROLLBACK;
SELECT * FROM student;
```

事务内的第一次查询看不到 Alice；回滚后的查询可以再次看到 Alice。图形界面的“开始事务”“提交”“回滚”按钮对应同名 SQL 语句。

### 7.3 提交一组操作

```sql
BEGIN;
INSERT INTO student(id, name, age) VALUES (4, 'Carol', 21);
COMMIT;
SELECT * FROM student;
```

提交成功后 Carol 会保留，重新打开同一目录仍可查询。

### 7.4 事务出错与并发访问

显式事务中 SQL 出错后，必须执行 `ROLLBACK;`，不能直接继续提交。GUI 会显示“事务出错 · 请回滚”。建表和删表也参与事务回滚。

多个页面或进程可以连接同一数据库，但显式事务会占用整库独占锁；其他连接的查询也可能需要等待。

- 图形界面的锁等待时间为 1 秒，超时显示 `DATABASE_BUSY`。
- 命令行默认等待 5 秒，可通过 `--lock-timeout` 调整。
- 结束持锁连接的事务后，其他连接可以重试。
- 当前不支持嵌套事务、保存点、行锁或 MVCC。

不要将“页面已断开”“请求网络失败”直接理解为“写入没有生效”。自动提交语句若已在服务端完成，应重新连接并查询核实。

## 8. 编译过程与缓存统计

### 8.1 编译分析

运行 SQL 后，切换到“编译分析”，通过语句选择框查看成功编译的各条语句。

| 阶段 | 展示内容 |
|---|---|
| Token 流 | 词法类型、词素、行号和列号 |
| AST | 可展开的抽象语法树 |
| 语义检查 | 检查结论及绑定后的表、列等信息 |
| 执行计划 | 优化前后的算子结构与表达式 |

数据来自真实编译调用，界面不会为生成分析结果再次执行 SQL。编译成功不代表执行或提交成功；编译失败的语句没有完整分析快照，应查看执行结果中的错误。

### 8.2 缓存统计

![缓存统计界面](assets/gui-cache.png)

| 指标 | 含义 |
|---|---|
| 命中 | 请求页已在页缓存中的次数 |
| 缺失 | 请求页不在页缓存中的次数 |
| 命中率 | 命中 ÷（命中 + 缺失）；没有访问时显示“—” |
| 淘汰 | 为腾出缓存空间而移除页的次数 |
| 脏页写回 | 成功将修改后的缓存页写回页管理器的次数 |
| 替换日志 | 被淘汰页的编号、是否为脏页和替换策略 |

GUI 显示最近一次执行结束时，当前连接所持有缓存的快照。新事务会重建缓存，回滚后显示恢复后的缓存；其中可能包含目录访问。刷新左侧表结构不会覆盖最近执行的展示数据。

**这些指标不是整批 SQL 的累计统计，也不是物理磁盘 I/O、fsync 次数或 SQL 吞吐量。** 图形数据库连接当前使用 LRU、64 页缓存；LRU/FIFO 对比通过独立实验运行。

## 9. 命令行与 SQL 文件

### 9.1 交互输入

```powershell
# 与图形界面的默认目录保持一致
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\gui
```

终端显示 `minisql>` 后输入 SQL。语句未结束时出现续行提示 `...>`；补齐分号后执行。字符串和注释中的分号不会作为语句结束标志。

- 单独输入 `exit` 或 `quit` 退出，不加分号。
- 有未完成输入时，Ctrl+C 取消本次输入；没有未完成输入时退出。
- 退出时未结束的显式事务会回滚。
- 退出时存在残缺 SQL，会提示原因且不执行残缺内容。

### 9.2 执行 SQL 文件

```powershell
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\file-demo --file .\examples\core.sql
```

`core.sql` 包含建表、插入、查询和删除。首次运行应使用新的练习目录；重复运行同一目录会遇到同名表错误。

成功执行文件返回退出码 0，SQL 错误返回 1。文件结束时仍有未提交事务，也会回滚并返回 1。失败批次保留之前自动提交的结果。

### 9.3 常用参数

| 参数 | 用途 |
|---|---|
| `--data-dir` | 指定数据库目录，命令行默认 `data` |
| `--file` | 执行 UTF-8 SQL 文件；省略时进入交互输入 |
| `--trace` | 执行 SQL，并输出编译过程和结果的 JSON Lines |
| `--lock-timeout 10` | 将锁等待时间设置为 10 秒；0 表示立即检查 |
| `--help` | 查看帮助 |
| `--version` | 查看版本 |

### 9.4 教学实验入口

```powershell
# 编译跟踪：该选项会实际执行 SQL；此示例最后回滚
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\trace-demo --file .\examples\trace.sql --trace

# 独立页缓存实验，比较 LRU/FIFO 与不同容量
.\.venv\Scripts\python.exe -m minisql.cli.cache_experiment --capacities 2 3 4 --rounds 3

# 端到端演示与断言验证
.\.venv\Scripts\python.exe examples\demo.py
```

缓存实验使用独立临时文件，不直接修改图形工作台连接的数据库。统计口径及更多参数参见 [编译跟踪与缓存实验](编译跟踪与缓存实验.md)。

## 10. 数据保存与退出

数据库目录中主要包含：

| 文件 | 用途 |
|---|---|
| `minisql.db` | 数据库页文件，包含表结构和记录 |
| `minisql.lock` | 协调连接和进程访问的锁文件 |
| `minisql.journal` 等日志文件 | 事务和异常退出恢复过程中使用，是否存在取决于事务状态 |

已提交的数据保存在当前连接目录。重新打开时使用同一目录即可访问，不能只根据浏览器中的数据库名称判断是否是同一份数据。

正常退出流程：

1. 确认需要保留的操作已经提交；不需要保留的操作回滚。
2. 在图形界面断开连接，或从 CLI 正常退出。
3. 若使用图形服务，在启动窗口按 Ctrl+C 关闭服务。

异常退出后，重新打开同一目录会尝试恢复。不要手动删除恢复日志来绕过错误；恢复失败时保留原目录及错误信息。

如需文件级备份，应先正常结束所有使用该目录的连接和服务，再复制整个数据库目录。不要在仍有写入事务时只复制一个正在变化的数据文件。

## 11. 常见问题

| 现象 | 检查与处理 |
|---|---|
| 双击后提示找不到 Python 或 `py` | 安装 Python 3.11+，或按第 2 节创建项目虚拟环境 |
| 浏览器无法连接 | 检查启动窗口是否仍运行，使用窗口打印的地址；端口更改后同步修改网址 |
| 提示端口被占用 | 如果已有工作台服务，可打开原地址；否则用 `--port 8767` 等指定其他端口 |
| 连接后没有以前的表 | 检查完整目录；GUI 默认 `data/gui`，CLI 默认 `data` |
| 重复加载示例后建表报错 | 示例表已存在，只执行需要的查询，或使用新的练习目录 |
| INSERT 报列数、列名或类型错误 | 列出全部表列，按对应顺序提供值；INT 不使用单引号，字符串使用单引号 |
| 缺分号或字符串未闭合 | 补齐语句末尾分号及单引号，按错误位置检查 |
| `TRANSACTION_ABORTED` | 当前显式事务出错，先执行 ROLLBACK |
| `DATABASE_BUSY` | 其他连接可能持有未结束事务；提交、回滚或断开持锁连接后重试 |
| 会话超时 | 页面会话空闲 30 分钟后释放，未提交事务回滚；刷新后重新连接 |
| 执行时报错，但部分数据发生了变化 | 批次中此前自动提交的操作可能已完成，重新 SELECT 核实 |
| `EXPRESSION_TOO_COMPLEX` | 简化 WHERE；其左括号和运算符总数预算为 64 |
| `INTEGER_OUT_OF_RANGE` | 检查数值或加减结果是否超出有符号 64 位范围 |
| SQL 文件无法打开或乱码 | 使用 UTF-8 保存，检查文件大小及引号格式 |
| 删除记录后文件没有缩小 | 页内空间会复用，数据库文件不主动缩小；这不代表删除失败 |

## 12. 当前限制与相关文档
