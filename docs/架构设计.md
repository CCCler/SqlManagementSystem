# MiniSQL 架构设计

## 设计依据与范围

依据《大型平台软件设计实习》指导书、总体 PPT 与 SQL 编译器专项 PPT。
指导书要求完成 SQL 编译器、页式存储和可交互数据库，至少执行 CREATE TABLE、INSERT、SELECT、DELETE，
表数据与 Catalog 都必须经页式存储持久化。专项 PPT 补充 AST、可定位错误、计划优化及验收要求。

当前实现已贯通编译器、页式存储、执行器与 CLI；截至 2026-09-09，已同步远程引擎报告、演示脚本和错误测试，并扩展 DROP TABLE、交互输入处理、记录空间回收和事务恢复，全套测试 354 项通过，无跳过。
已支持 INT/VARCHAR、内部 BOOL、比较和布尔表达式，并实现常量折叠与布尔化简。
JOIN、GROUP BY、索引尚未实现；事务与恢复采用整库独占锁和完整文件前映像日志。

## 分层与依赖

| 层 | 职责 | 允许依赖 |
|---|---|---|
| contracts | 类型、AST、计划、错误、Protocol | 标准库 |
| compiler | 切词、解析、语义、计划、优化 | contracts、编译器内部 |
| storage | 文件、页、缓冲池、记录存储 | contracts、存储内部 |
| engine | Catalog、算子、生命周期、装配 | contracts、compiler、storage |
| cli | 参数、交互、输出 | engine、contracts、compiler.statements（共享边界扫描） |

执行入口先切分语句，然后对每条语句依次编译、执行、刷新。
不能先对整个文件做语义检查：前一条 CREATE TABLE 必须先执行，后一条 INSERT 才能解析新表。

数据流：

```text
CLI → Database → SQLCompiler → AST / Semantic / Plan / OptimizedPlan
             ↓                         ↑
        PlanExecutor ←─────────────── Plan
             ↓                         ↑
        HeapStorage ← PersistentCatalog（编译器只读查询）
             ↓
        PageBufferPool → DiskPageManager → FileManager → 磁盘
```

## 关键边界

- 编译器不创建物理表，不修改 Catalog；名字解析通过 CatalogReader。
- 成员二统一负责 Row ↔ Page，包括编码、槽目录、空闲空间和表页映射。
- 成员三处理算子和元数据。SeqScan/Filter 保留 StoredRecord 的 RecordId；
  SELECT 的 Project 产生结果列，DELETE 只接收扫描或过滤结果。
- AST 和 Plan 是不可变 dataclass；优化生成新计划，以便展示优化前后差异。
- 分析成功返回 SemanticResult，业务错误抛出 MiniSQLError，包含阶段、错误码、原因和可用的位置；语法错误还提供期望符号。
- 编译结果保留 Token、AST、SemanticResult、原计划和优化计划。Database 执行优化计划，CLI 默认显示执行结果，不展示编译中间结果。
- 标识符规范化为小写；INSERT 值按表列顺序重排，SELECT 星号展开明确列名；WHERE 必须为 BOOL。
- 比较要求两侧同类型，严格区分 BOOL 与 INT；字符串排序比较按 Python 字符串字典序执行，与优化器一致，不按拼音排序。
- 多语句片段保留文件级行列。遇错停止后续编译执行，自动提交模式保留此前成功语句；显式事务出错后必须回滚，失败时不返回部分结果列表。

## 持久化与启动

默认页大小 4096 字节，缓存容量 64 页，默认 LRU；通过 PageBufferPool 构造参数可选择 FIFO，CLI 暂未提供缓存配置选项。
存储模块持久化页分配信息和 table_id 到数据页的映射；业务代码不依赖其磁盘格式。
INT 使用有符号 64 位整数，VARCHAR 使用 UTF-8 长度前缀编码；超单页记录第一版明确拒绝。

table_id=0 保留给 __catalog；其结构固定在 engine/catalog.py。
新库通过存储接口创建系统表；重启时通过固定结构直接读取系统表，不经过 SQL 编译。
系统表记录 table_id、表名、列序号、列名和列类型，用户表编号从 1 开始。
引擎先创建物理表取得 table_id，再注册目录，写操作仍经存储 flush，提交额外同步数据文件并持久化日志提交标记。
事务开始前保存整库前映像，失败或崩溃可恢复目录、页分配信息和记录；close 回滚未提交事务。

open_database 创建数据目录，在操作系统独占锁内恢复日志，再装配 minisql.db 的页、缓存、记录、目录和编译执行模块；每个新事务持锁重载，避免使用其他连接提交前的旧缓存。
页管理器的空闲页复用已实现；HeapStorage.delete 将存活记录字节整理到页尾，保留存活槽编号，回收已删除负载并移除尾部空槽；插入优先复用中间空槽，避免槽目录无限增长。旧版本墓碑在该页再次插入或删除时整理，无需更改磁盘格式。

## DROP TABLE 扩展

SQL 编译生成 DropTable 计划，执行器核对当前表编号，存储层验证页链并清除根映射、丢弃缓存、释放数据页；目录层删除对应系统表记录并刷新。
禁止删除系统目录表；同名重建使用新表编号，旧计划不能误删新表。单条 DELETE 回收页内空间，保留表的页链供后续插入；整表 DROP 则释放整条数据页链。
已验证空表、跨页表、其他表隔离、重启后不存在、同名重建、缓存失效和页复用；通过事务入口执行时支持整组回滚和崩溃恢复，包括 DROP 后同名重建。

删除后的 RecordId 不得继续使用，空槽可能被新记录复用；存活记录的 RecordId 不因页内整理变化。无 ORDER BY 的扫描结果不承诺插入顺序。
已通过 17 项空间回收专项测试，涵盖字节整理、反复增删、空页容量、旧文件墓碑、跨页/重启、混合操作及错误 RecordId 保护。

## 事务、并发与崩溃恢复扩展

TransactionalDatabase 管理状态、自动提交和线程归属；storage.journal 提供操作系统锁及写前回滚日志。
BEGIN 获取整库独占锁，恢复遗留日志，持久化完整前映像后才允许数据修改；COMMIT 先刷新和同步数据库，再持久化提交标记，最后清理日志并释放锁。
ROLLBACK 丢弃旧缓存并恢复文件；恢复未完成时保留日志，下次打开可再次恢复。完整提交标记表示保留新数据，半标记按未提交恢复。
多个连接/进程按事务串行访问，读取也需要独占锁；同连接自动语句用线程锁保护，显式事务绑定发起线程。
24 项事务与并发专项、18 项恢复专项通过，包含真实子进程强退、恢复再次中断、I/O 故障注入、日志损坏拒绝覆盖、多进程读改写与线程竞争。
实现没有行锁、MVCC 或增量 redo WAL；未进行真实断电和介质损坏恢复验收。文件协议、使用方法及成本见 [事务与恢复](事务与恢复.md)。

## 编译可观测性与复杂度保护

Parser 在递归前限制 WHERE 结构复杂度为 64，覆盖括号、连续 NOT 与二元表达式链，防止后续递归阶段溢出。
CLI TracingCompiler 包装真实编译器，在同一持锁编译调用后序列化全部结果，不重复编译；--trace 输出 JSON Lines，仍然执行 SQL。
独立页缓存实验重放同一访问序列，比较 LRU/FIFO 及持续/每轮重建缓存；统计包含轮末写回，使用真实页文件并重开校验，实验不等同于 SQL 性能测试。
说明与演示命令见 [编译跟踪与缓存实验](编译跟踪与缓存实验.md)。
