# 事务、并发与崩溃恢复

通过 `open_database()` 创建的连接以及 CLI 支持下述协议。数据页格式不变，已有数据库可以直接打开。

## 使用与失败行为

默认每条 SQL 是一个自动提交事务。使用 `BEGIN;` 开始显式事务，`COMMIT;` 保存整组修改，`ROLLBACK;` 撤销整组修改。
CREATE TABLE、DROP TABLE、INSERT、DELETE 均参与事务，Catalog、页分配信息与记录一起提交或回滚。
显式事务中任何 SQL 出错后必须回滚；此时 COMMIT 和普通 SQL 返回 TRANSACTION_ABORTED。
不支持嵌套事务、保存点、BEGIN TRANSACTION。BEGIN、COMMIT、ROLLBACK 是保留关键字。

```python
from pathlib import Path
from minisql.engine.database import open_database

db = open_database(Path("data/transaction-demo"), lock_timeout=5.0)
try:
    db.begin()
    db.execute("CREATE TABLE example(id INT);")
    db.execute("INSERT INTO example(id) VALUES (1);")
    db.commit()
except Exception:
    if db.in_transaction:
        db.rollback()
    raise
finally:
    db.close()
```

示例首次运行使用新目录；表已存在时会报错并回滚。close 自动回滚未提交事务。
CLI 在文件结束、exit/quit 或 EOF 时发现未提交事务，会回滚、说明原因并返回退出码 1。
COMMIT_UNCERTAIN 表示提交标记的持久化未得到确认；必须重新打开连接、查询结果后决定是否重试，不能假定提交或回滚已经成功。

## 并发约定

每个事务持有数据库级操作系统独占锁直到结束，包括只读查询。不同连接、线程及进程可以连接同一目录，但事务串行执行；其他连接无法读取中间状态。
默认锁等待 5 秒，超时返回 DATABASE_BUSY，之后可重试。API 的 lock_timeout 和 CLI 的 --lock-timeout 接受有限非负秒数，0 表示立即检查。
事务获取锁后重新加载 Catalog 与缓存，避免旧连接覆盖新提交。单连接的自动语句由线程锁串行化；显式事务只能由开始它的线程执行，其他线程返回 TRANSACTION_OWNER。

保证仅适用于连接的 execute/begin/commit/rollback。不能通过 storage、catalog、executor 绕过入口修改文件，不能跨事务持有底层对象或缓存引用。
锁文件必须保留，运行中删除它会破坏互斥。部署目标为支持文件锁的本地文件系统，不承诺网络共享目录的锁与同步语义。

## 文件与提交协议

| 文件 | 用途 |
|---|---|
| minisql.db | 原有页式数据库，包含系统目录及用户记录 |
| minisql.lock | 稳定的操作系统锁载体，进程退出后锁由系统释放 |
| minisql.journal.tmp | 准备中的日志，发布前不得修改数据库 |
| minisql.journal | 已发布的完整事务前映像，恢复所需，不能手工删除 |

日志头采用大端 `>8sQ32s`，共 48 字节：魔数 `MSQLUNDO`、8 字节前映像长度、32 字节 SHA-256 校验值；其后是该长度的数据库原始字节。
日志尾部为空或提交标记 `MSQL-COMMITTED\n`。完整标记表示提交决定；标记的严格前缀表示写入中断，按未提交处理。其他尾部或校验错误返回 CORRUPT_JOURNAL，保留文件，停止恢复。

1. 获取独占锁，先处理遗留日志。
2. 将数据库完整旧内容写入临时日志，flush 和 fsync，再发布为正式日志。
3. 修改页和系统目录；允许缓存提前写回，因为旧内容已被日志保护。
4. COMMIT 刷新所有脏页、同步数据文件及支持平台的目录，再追加提交标记并同步日志。
5. 清理日志，释放锁。提交标记已持久化后的清理失败交给下次恢复，不能误报回滚。

POSIX 使用原子替换与目录 fsync；Windows 发布日志使用 MoveFileExW 的 REPLACE_EXISTING 与 WRITE_THROUGH，数据和日志使用 fsync。
恢复未提交事务时，用前映像覆盖并截断数据库，同步完成后才删除日志。恢复过程中再次中断仍保留日志，下次打开重复恢复。
已有完整提交标记则保留数据库新内容，只清理日志。恢复和回滚均丢弃旧缓存，避免旧脏页覆盖恢复结果。
非空数据库不足一页或元信息魔数错误时拒绝打开，不能把损坏文件当新库初始化。

## 已验证范围与成本

24 项事务/并发与 18 项恢复专项通过；全套 354 项通过，无失败、无跳过。
测试包括真实子进程强制退出、提交前/半标记/完整标记后退出、恢复再次中断、DROP 后同名重建、损坏日志、同步故障与提交结果不确定。
多个独立进程执行读取—修改—提交验证无丢失更新；线程测试覆盖锁等待、连接刷新及事务线程归属。

这是适合教学数据量的完整前映像 undo journal，不是增量 redo WAL 或 ARIES。每次事务开始（包括自动提交查询）复制整个数据库，时间、内存和额外磁盘空间为 O(数据库大小)。
独占锁限制吞吐量，长事务会阻塞其他查询。尚无行锁、MVCC、保存点、增量日志、在线备份与介质损坏修复。
已实测进程崩溃及故障注入，未进行真实断电实验；持久性仍依赖操作系统、文件系统和硬件正确执行同步请求。
