# 公共接口约定（第一版）

公共类型定义于 src/minisql/contracts；跨模块扩展同步维护实现、测试替身和本文约定。本版新增 DROP TABLE 与事务控制相关类型和接口。

## 数据与错误

- SourcePosition 行列从 1 开始；Token 保留原始词素。关键字与未加引号的标识符大小写不敏感，语义名称统一小写，字符串保持原样。
- TableSchema.columns 保持建表顺序。table_id=None 表示未分配，0 保留系统表，用户表从 1 开始。
- Row 是按表列顺序排列的 tuple；RecordId=(page_id, slot_id)，扫描返回 StoredRecord。
- 第一版只允许 INT/VARCHAR 表列，BOOL 仅用于表达式。bool 不得因 Python 的继承关系被当成 INT。
- 不支持 NULL/列默认值，因此 INSERT 必须提供全部列，允许调整列名顺序，规划阶段重排值。重复列、漏列、多列均报语义错误。
- INT 使用有符号 64 位范围；字符串使用 UTF-8。记录不跨页，超出单页容量报 storage 错误。运行时加减结果越界报 EXECUTION:INTEGER_OUT_OF_RANGE。
- MiniSQLError 包含 stage、code、reason、position、expected。解析错误填写期望符号；无 SQL 位置的 I/O 错误允许 position=None。
- 建议稳定错误码：UNKNOWN_TABLE、UNKNOWN_COLUMN、TYPE_MISMATCH、DUPLICATE_TABLE、INVALID_RECORD、INTEGER_OUT_OF_RANGE、IO_ERROR。
- 业务失败通过 MiniSQLError 报告；禁止删除系统目录表，错误码为 PROTECTED_TABLE。

## 编译与计划

| 方法 | 约定 |
|---|---|
| split_statements(sql) | 按字符串/注释状态识别分号；不能直接 split(';') |
| compile(sql, catalog) | 编译一条语句；返回 CompilationResult，保留所有中间结果 |
| tokenize(sql) | 返回包含 EOF 的 Token 元组 |
| parse(tokens) | 构建 CREATE/INSERT/SELECT/DELETE/UPDATE/DROP/EXPLAIN 及 TransactionStmt，使用递归下降 |
| analyze(statement, catalog) | 检查名字、类型、INSERT 列映射；返回 SemanticResult |
| build(semantic) | 生成 CreateTable/Insert/SeqScan/Filter/Project/Delete/Update/DropTable/TransactionControl/Explain |
| optimize(plan) | 返回新计划，不修改原计划 |

为保持多语句的文件级位置，split_statements 返回的每个片段，在原有起始位置前用空白替换之前非换行字符，
保留所有原始换行；编译器因此可以直接计算全文件行列。空白及仅注释输入返回空元组。
缺分号的非空尾部保留并交给 Parser 报错。仅处理词法层切分，不提前进行整批语义检查。

SelectStmt.columns=None 表示星号；distinct/limit 分别表示去重与截断，计划中的 Project 展开成明确列名并携带同名字段。
EXPLAIN 生成 Explain 计划，执行器仅渲染优化后计划树、不扫描也不修改数据；语义检查仍先执行。
WHERE 必须得到 BOOL。名字绑定至少完成规范化标识符与唯一表结构的核对；第一版只有单表，无歧义解析。
Delete 的 source 只允许 SeqScan/Filter 链，禁止丢失 RecordId。
DropTableStmt 保存表标识符与位置，DropTable 计划保存绑定的 TableSchema；编译只检查，不删除表。

## Catalog 与存储

| 方法 | 约定 |
|---|---|
| get_table(name) | 返回 TableSchema，不存在返回 None |
| list_tables() | 返回用户表，不暴露系统表 |
| bootstrap() | 通过固定系统表结构初始化新库或恢复已有目录 |
| register_table(schema) | 注册已分配编号的表；重复表名报错 |
| unregister_table(name) | 删除该表的系统目录记录并刷新，移除内存目录项；不存在或为系统表时报错 |
| create_table(schema) | 返回含稳定 table_id 的新结构；不更新 Catalog |
| drop_table(schema) | 验证数据页链，清除根页映射，丢弃对应缓存并释放整表数据页；不更新 Catalog，禁止 table_id=0 |
| insert(schema, row) | 返回 RecordId；检查记录编码和大小 |
| scan(schema) | 返回完整记录迭代器；跳过已删除记录，保留记录标识 |
| delete(schema, record_id) | 验证记录属于目标表，删除并整理页内空间；无效或已删除标识报错 |
| rewrite_table(schema, new_schema, transform) | 整表存活记录重写为 new_schema；transform 返回新行或 None（丢弃该行）；先全部转换编码，再写全新页链，成功后才原子切换 root_page 并回收旧页链；失败保持旧数据不变。返回含 table_id 的新结构；不更新 Catalog，事务安全由调用方负责 |
| flush()/close() | 刷新数据与存储分配信息；close 同时释放文件资源 |

create_table 在 schema.table_id=None 时分配新用户表；指定 0 仅供系统表引导，重复分配必须报错。
页管理器提供 allocate/free/read/write；read 返回完整定长 bytes，write 长度必须等于 page_size。
缓存 get_page 返回页的可变内容，修改后调用 mark_dirty；该引用只在下一次缓存访问前有效。
需要新页或释放页时，记录层协调刷新并确保没有继续持有被回收页的缓存引用，避免脏页覆盖。
缓存策略、脏页写回、命中/缺失/淘汰统计与 ReplacementEvent 日志归成员二。
BufferPool.discard_page(page_id) 丢弃缓存和脏标记，不写回，用于数据已作废且即将释放的页；调用后旧页引用不可继续使用。

执行器先核对 DropTable 绑定编号仍与当前 Catalog 一致，再调用 storage.drop_table、catalog.unregister_table 和 flush。
同名重建分配新 table_id，旧计划不能删除重建后的表；已释放的数据页可复用，数据库文件不主动缩小。
通过 open_database 的 SQL 执行入口删除表时，物理页和目录变更属于同一事务，可一起回滚；直接调用底层接口不提供此保证。

存储磁盘格式（页头 24B、槽 5B、页 0 元信息、空闲页链表、table_id→根页映射、
记录编码）详见 docs/storage_format.md，关键跨模块约定如下：

- 页 0 为存储元信息页，持久化 next_page_id / next_table_id / free_list_head 及 root_page 映射区。
- 根页映射显式持久化：页 0 映射区下标 = table_id，值为根页号；table_id=0 对应 __catalog。
- 记录编码：INT 用 8 字节有符号大端（>q），VARCHAR 用 2 字节长度前缀 + UTF-8。
- 记录不跨页，单条记录最大 4067 字节（4096 - 页头24 - 槽5），超限报 INVALID_RECORD。
- 格式版本存页 0 页头 reserved 字节：V1=1（仅 INT/VARCHAR）、V2=2（新增 NULL 与
  BOOL/DECIMAL/DATE/TIME/TIMESTAMP）；历史文件该字节为 0，读取时归一化为 V1，
  旧库可读、不自动迁移。新库写 V2，V1 编解码遇到新类型或 NULL 报 TYPE_MISMATCH。
- 表结构变更（F06）的存储层能力为 rewrite_table（见上表）；ALTER 的语法、Catalog
  更新与事务由成员一/三负责，存储层只保证数据结构重写与失败不破坏旧数据。
- V1→V2 迁移为独立工具 minisql.engine.migrate / `python -m minisql.cli.migrate`
  （默认预演，`--apply` 才写；迁移前默认备份，保留 table_id，中断可重跑且幂等）；
  “未经确认不转换业务目录”。格式与操作细节见 docs/storage_format.md 第 10 节与
  docs/存储迁移说明.md。

## 系统入口

open_database(path, *, lock_timeout=5.0) 返回 TransactionalDatabase，组装存储、目录与编译执行模块。
在独占锁内先恢复日志，再引导系统表。lock_timeout 必须是有限非负秒数。
execute(sql) 顺序处理片段，正常返回 ExecutionResult 列表；遇错停止，不返回部分结果列表。
默认每条 SQL 自动提交，失败语句回滚，之前已提交的语句保留。
BEGIN 后直到 COMMIT/ROLLBACK 为同一事务，任何 SQL 错误将其标为失败，必须 ROLLBACK；close 自动回滚未提交事务。
begin()/commit()/rollback() 等价于对应 SQL，返回单个 ExecutionResult；in_transaction 表示是否存在显式事务。
TransactionStmt(action, position) 编译为 TransactionControl(action)，SemanticResult.schema 为 None；由数据库层处理控制计划。
原 Database 注入式装配类用于模块隔离测试，不提供事务；直接调用 executor/storage/catalog 也不受事务保护。
不得跨事务保留旧缓存、Catalog 或存储对象引用；显式事务只能由开始它的线程执行 SQL。
正常退出及异常退出均应调用 close，禁止吞掉关闭错误。

事务错误码包含 NO_TRANSACTION、TRANSACTION_ACTIVE、TRANSACTION_ABORTED、TRANSACTION_OWNER、DATABASE_BUSY、CONNECTION_CLOSED。
COMMIT_UNCERTAIN 表示提交决定未确认，连接不可继续使用，重新打开后查询核实，不能直接假定已回滚或盲目重试写入。
CORRUPT_JOURNAL/CORRUPT_DATABASE 表示损坏，保留文件并停止打开，不自动清空初始化。协议见 [事务与恢复](事务与恢复.md)。

## 交互输入边界

CLI 与 SQLCompiler.split_statements 共用 scan_statements，扫描只报告完整语句末尾、字符串/块注释状态和是否有未完成尾部，不提前语义检查。
文件执行仍将非空残缺尾部交给 Parser/Lexer 报错；交互模式执行完整前缀，保留尾部等待续行。退出或 EOF 不执行残缺尾部，输出原因并返回 1；空白及完整注释不算残缺 SQL。
Ctrl+C 在存在待续输入时取消并继续会话，空闲时退出；字符串和块注释内的 exit/quit 不解释为退出命令。

## 记录空间回收

DELETE 保持存活记录的 page_id/slot_id，不移动槽编号，只更新负载偏移；删除槽负载清空，中间空槽供 INSERT 复用，尾部空槽裁剪。
已删除 RecordId 生命周期结束，复用后可能指向新记录，不支持使用旧标识重复操作。未复用前重复删除报 INVALID_RECORD。
空数据页继续留在原表页链中，支持同表插入复用，不缩小文件；整表页释放由 DROP TABLE 负责。旧版本删除标记在页再次写入时一并回收，兼容现有文件格式。

## 编译跟踪与缓存实验

Parser 对 WHERE 结构 Token 使用 64 项预算，超限返回 syntax:EXPRESSION_TOO_COMPLEX，position 指向超限 Token，expected 为 SIMPLER_EXPRESSION。
CLI --trace 以 JSON Lines 输出真实编译结果及执行结果，不改变事务语义；compilation 不代表执行或提交成功。
PageBufferPool.writebacks 为成功脏页写回次数（含主动刷新及淘汰）；保留原 CacheStats 的三字段接口，失败写回不计数且保留脏页。
独立缓存实验入口为 python -m minisql.cli.cache_experiment，比较持续缓存与每轮重建缓存，统计不包含 SQL、事务日志与目录开销。详见 [编译跟踪与缓存实验](编译跟踪与缓存实验.md)。

UPDATE 使用 UpdateStmt（赋值列表与 WHERE）和 Update 计划，源节点保留 RecordId。执行器固定匹配集合，所有赋值读取旧行，先求值后通过现有 insert/delete 替换记录；不新增 RecordStorage 接口或修改文件格式。受影响记录的 RecordId 可能改变，原子性由 TransactionalDatabase 的现有事务日志提供。


## SQL 扩展编译契约（成员一交付）

完整定义见 `src/minisql/contracts/extensions.py` 和 [编译器报告](SQL扩展编译器报告.md)。

- `compile(sql,catalog)` 和 `split_statements(sql)` 签名不变；CompilationResult 新增 output_fields、dependencies、required_capabilities，默认空元组保持调用兼容。
- Statement 新增 Query/Command；Plan 新增 ExtendedPlan；SemanticResult 的 statement 可为 BoundStatement。旧语句仍保留旧 AST/Plan。
- ColumnSchema 保留 name/data_type 的构造方式，新增 precision/scale/nullable/default/has_default；TableSchema 新增 constraints。Value 可为 None、Decimal、date/time/datetime、BOOL。这里只扩展描述，不代表记录存储已支持这些值。
- FieldBinding 用 scope/source/ordinal 唯一绑定字段，qualifier/name 供展示。执行器不能仅按名字读取关联、自连接或相关子查询字段。
- ExtendedCatalogReader 为只读协议。真实目录由 ReadOnlyCatalogAdapter 转接；不支持的必要扩展查询报 CATALOG_CAPABILITY_UNAVAILABLE。成员三提供的对象必须是实际元数据，不能用默认空集合绕过对象检查。
- ExtendedPlan 表达式中的子查询、所有 children 及 Schema 属性均应纳入接入检查。PlanExecutor 当前统一拒绝新计划和含新属性的旧计划，报 FEATURE_NOT_EXECUTABLE；Explain 是只读展示例外。
- capabilities 是接入需求说明，不构成授权。最终授权必须在统一数据库入口对调用者身份检查，覆盖视图、子查询及触发动作。
- 序列化必须调用 cli.trace.to_json_value；敏感字段不输出，Decimal 为字符串，日期为 ISO，None 为 null。不得记录原始密码 SQL。
- 索引键按 IndexDefinition.columns 顺序，包含 TypeSpec；记录定位沿用 RecordId。物理键编码、页接口及事务维护尚由成员二实现，本次不分配系统表编号。
- 运行期必须落实标量多行错误、三值逻辑、NULL 分组/排序、约束行验证、Decimal 舍入/溢出、触发器共同回滚及最终鉴权。具体类型公式、权限组合和依赖要求见报告。

## 2026-09-12 最终验收补充

本文件第一版限制描述旧计划路径；新类型、NULL、约束、索引及十二类扩展以扩展契约和[最终验收报告](最终验收报告.md)为准。

- `RecordStorage.fetch(schema, record_id) -> StoredRecord`：索引回表按记录位置读取；验证页类型、页编号、表归属、槽范围及删除标记。非法记录报 `STORAGE:INVALID_RECORD`，不存在的表报 `UNKNOWN_TABLE`。旧页头归属为零时验证页链归属。真实堆存储与内存测试替身均实现。
- `BTreeIndex.range_scan` 的上下界接受非空最左列前缀。包含边界表示包括整个同前缀键组，排除边界表示排除该组。完整 WHERE 保留为残余检查。
- `SetOperation.attributes` 新增 `output_scope`，集合结果绑定到 `(output_scope, 0)`，供排序等上层算子引用。
- 扩展 UPDATE 先计算最终行集并验证约束，再移除旧记录和旧索引项，写入新记录和新索引项；多列赋值仍使用更新前的值。写入失败由事务机制恢复。
- INT 到 DECIMAL 的无损提升在 SQL 写入与表重写边界完成；不放宽底层编码器的类型与精度校验。
