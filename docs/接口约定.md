# 公共接口约定（第一版）

公共类型定义于 src/minisql/contracts；三人共同确认后修改。所有业务签名已有对应骨架。

## 数据与错误

- SourcePosition 行列从 1 开始；Token 保留原始词素。关键字与未加引号的标识符大小写不敏感，语义名称统一小写，字符串保持原样。
- TableSchema.columns 保持建表顺序。table_id=None 表示未分配，0 保留系统表，用户表从 1 开始。
- Row 是按表列顺序排列的 tuple；RecordId=(page_id, slot_id)，扫描返回 StoredRecord。
- 第一版只允许 INT/VARCHAR 表列，BOOL 仅用于表达式。bool 不得因 Python 的继承关系被当成 INT。
- 不支持 NULL/列默认值，因此 INSERT 必须提供全部列，允许调整列名顺序，规划阶段重排值。重复列、漏列、多列均报语义错误。
- INT 使用有符号 64 位范围；字符串使用 UTF-8。记录不跨页，超出单页容量报 storage 错误。
- MiniSQLError 包含 stage、code、reason、position、expected。解析错误填写期望符号；无 SQL 位置的 I/O 错误允许 position=None。
- 建议稳定错误码：UNKNOWN_TABLE、UNKNOWN_COLUMN、TYPE_MISMATCH、DUPLICATE_TABLE、INVALID_RECORD、IO_ERROR。
- 此处只约定业务行为；当前占位统一 NotImplementedError，不伪造业务返回值。

## 编译与计划

| 方法 | 约定 |
|---|---|
| split_statements(sql) | 按字符串/注释状态识别分号；不能直接 split(';') |
| compile(sql, catalog) | 编译一条语句；返回 CompilationResult，保留所有中间结果 |
| tokenize(sql) | 返回包含 EOF 的 Token 元组 |
| parse(tokens) | 构建四类 Statement，使用递归下降 |
| analyze(statement, catalog) | 检查名字、类型、INSERT 列映射；返回 SemanticResult |
| build(semantic) | 生成 CreateTable/Insert/SeqScan/Filter/Project/Delete |
| optimize(plan) | 返回新计划，不修改原计划 |

为保持多语句的文件级位置，split_statements 返回的每个片段，在原有起始位置前用空白替换之前非换行字符，
保留所有原始换行；编译器因此可以直接计算全文件行列。空白及仅注释输入返回空元组。
缺分号的非空尾部保留并交给 Parser 报错。仅处理词法层切分，不提前进行整批语义检查。

SelectStmt.columns=None 表示星号；计划中的 Project 展开成明确列名。
WHERE 必须得到 BOOL。名字绑定至少完成规范化标识符与唯一表结构的核对；第一版只有单表，无歧义解析。
Delete 的 source 只允许 SeqScan/Filter 链，禁止丢失 RecordId。

## Catalog 与存储

| 方法 | 约定 |
|---|---|
| get_table(name) | 返回 TableSchema，不存在返回 None |
| list_tables() | 返回用户表，不暴露系统表 |
| bootstrap() | 通过固定系统表结构初始化新库或恢复已有目录 |
| register_table(schema) | 注册已分配编号的表；重复表名报错 |
| create_table(schema) | 返回含稳定 table_id 的新结构；不更新 Catalog |
| insert(schema, row) | 返回 RecordId；检查记录编码和大小 |
| scan(schema) | 返回完整记录迭代器；跳过已删除记录，保留记录标识 |
| delete(schema, record_id) | 删除目标表记录；无效标识报错 |
| flush()/close() | 刷新数据与存储分配信息；close 同时释放文件资源 |

create_table 在 schema.table_id=None 时分配新用户表；指定 0 仅供系统表引导，重复分配必须报错。
页管理器提供 allocate/free/read/write；read 返回完整定长 bytes，write 长度必须等于 page_size。
缓存 get_page 返回页的可变内容，修改后调用 mark_dirty；该引用只在下一次缓存访问前有效。
需要新页或释放页时，记录层协调刷新并确保没有继续持有被回收页的缓存引用，避免脏页覆盖。
缓存策略、脏页写回、命中/缺失/淘汰统计与 ReplacementEvent 日志归成员二。

存储磁盘格式（页头 24B、槽 5B、页 0 元信息、空闲页链表、table_id→根页映射、
记录编码）详见 docs/storage_format.md，关键跨模块约定如下：

- 页 0 为存储元信息页，持久化 next_page_id / next_table_id / free_list_head 及 root_page 映射区。
- 根页映射显式持久化：页 0 映射区下标 = table_id，值为根页号；table_id=0 对应 __catalog。
- 记录编码：INT 用 8 字节有符号大端（>q），VARCHAR 用 2 字节长度前缀 + UTF-8。
- 记录不跨页，单条记录最大 4067 字节（4096 - 页头24 - 槽5），超限报 INVALID_RECORD。

## 系统入口

open_database(path) 组装 FileManager、DiskPageManager、PageBufferPool、HeapStorage、
PersistentCatalog、SQLCompiler、PlanExecutor 和 Database，随后 bootstrap。
Database.execute(sql) 顺序执行每个片段，返回 ExecutionResult 列表；
遇错抛出 MiniSQLError，停止后续语句，之前成功操作保持有效。正常结束返回全部结果，
失败时不返回部分结果列表；CLI 展示错误，用户可再次查询确认已完成操作。
正常退出及异常退出均应调用 close，禁止吞掉刷新错误。
