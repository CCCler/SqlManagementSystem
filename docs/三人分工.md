# 三人分工与协作实施表

适用项目：E:\zch_Projects\sql_project。成员一/二/三可替换为真实姓名。
目前交付的是骨架，以下工作清单均为后续开发任务，未勾选项不代表已完成。

## 责任与交付物

| 成员 | 主责文件范围 | 必须交付 | 独立测试依赖 |
|---|---|---|---|
| 成员一：SQL 编译器 | src/minisql/compiler、tests/compiler、docs/grammar.md | 文法、Lexer、Parser、AST 构造、语义检查、计划、两项优化、错误定位 | tests/fakes 中 MemoryCatalog |
| 成员二：存储系统 | src/minisql/storage、tests/storage | 文件/页管理、LRU/FIFO、RowCodec、HeapStorage、持久化及统计 | 固定 TableSchema 与数据 |
| 成员三：引擎与集成 | src/minisql/engine、cli、tests/engine、integration | 算子、Catalog 系统表、生命周期、CLI、端到端演示 | 人工 Plan 与 MemoryStorage |
| 共同维护 | contracts、项目配置、tests/contracts、接口文档 | 稳定的跨模块类型和接口 | 三人共同确认 |

存储引擎的行页映射全部归成员二；成员三只调用记录接口。
Catalog 的实际维护与持久化全部归成员三；成员一只调用只读查询接口。
公共 AST/Plan 由成员一提出调整，记录契约由成员二提出，系统结果由成员三提出，均需共同确认。

## Git 协作与接口变更

远程 origin 为 https://github.com/CCCler/SqlManagementSystem.git ，默认分支 main。
首次提交和同步尚未执行；先由组内负责人建立共同基线，再开始以下流程：

1. 成员一创建 feat/compiler，成员二创建 feat/storage，成员三创建 feat/engine。
2. 每次提交集中于一个模块/问题；测试与实现一起提交。
3. PR 写明行为、接口变化、测试结果和未完成项，由另一位组员审查。
4. 公共契约变更先在组内确认，再由一个人修改，并在同一 PR 更新调用方/模拟对象/文档。
5. 合并前运行全套测试；不以 skipped 数量证明功能完成，不提交数据文件或虚拟环境。
6. 联调失败由相关模块负责人修复，成员三负责复现与协调，不承担所有模块的修复。
