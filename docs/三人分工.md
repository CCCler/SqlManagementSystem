## Git 协作与接口变更

远程 origin 为 https://github.com/CCCler/SqlManagementSystem.git ，默认分支 main。
工程基线已提交并推送。三人在各自本地的 main 分支开发，直接推送到 origin/main：

1. 开始工作前确认当前分支为 main，工作区干净时执行 `git pull --ff-only origin main` 同步代码；若本地已有未推送提交，改按第 4 步同步。
2. 各自修改负责的模块，避免同时编辑同一文件。公共契约变更先在组内确认，由一人修改，并同步更新调用方、模拟对象和文档。
3. 完成一项工作后运行测试，检查改动，用中文说明创建本地提交；每次提交集中于一个模块或问题，测试与实现一起提交。
4. 提交后执行 `git pull --rebase origin main`。如有冲突，与相关组员确认，解决后暂存冲突文件并执行 `git rebase --continue`；有未完成的变基时不推送。
5. 同步完成后运行全套测试，通过后执行 `git push origin main`。若其他人先推送导致被拒绝，重复同步和验证，不使用强制推送。
6. 推送后向组员说明修改范围、接口变化和测试结果；不以 skipped 数量证明功能完成，不提交数据文件或虚拟环境。
7. 联调失败由相关模块负责人修复，成员三负责复现与协调，不承担所有模块的修复。
