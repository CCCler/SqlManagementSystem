# 成员二存储模块代码详解

> 本文面向答辩讲解，逐文件、逐类说明成员二负责的存储系统代码的功能、关键方法与设计动机。
> 代码位于 `src/minisql/storage/`，磁盘格式约定见 [storage_format.md](storage_format.md)，报告见 [storage_report.md](storage_report.md)。

## 0. 模块定位

存储系统是 MiniSQL 的最底层，向上为执行引擎提供 `RecordStorage` / `PageManager` / `BufferPool` 三个协议，
向下负责把表数据与 Catalog 真正落到磁盘文件 `minisql.db` 的 4KB 页上。

一句话概括：**把「表 + 行」映射到「4KB 页 + 槽」，并在内存缓存与磁盘之间正确、高效、可恢复地搬移字节。**

---

## 1. 文件清单与职责

| 文件 | 核心类 | 职责 |
|---|---|---|
| `file_manager.py` | `FileManager` | 数据库文件的随机读写、同步、关闭 |
| `page.py` | `DiskPageManager` | 页格式定义、页分配/释放/读写、页 0 元信息 |
| `record.py` | `RowCodec` / `HeapStorage` | 记录编解码；表级堆存储（建表/删表/插/扫/删） |
| `buffer.py` | `PageBufferPool` | LRU/FIFO 页缓存、脏页写回、命中与替换统计 |
| `journal.py` | `DatabaseLock` / `RollbackJournal` | 数据库级锁、写前回滚日志、崩溃恢复 |

依赖方向：`record.py` / `buffer.py` / `journal.py` 依赖 `page.py` 依赖 `file_manager.py`，全部依赖 `contracts` 的公共类型。

## 2. 磁盘页格式（核心数据结构）

每页固定 `PAGE_SIZE = 4096` 字节，分三部分：

```
偏移 0         页头（24 字节）
偏移 24        槽目录（每项 5 字节，向下增长）
               ... 空闲空间 ...
偏移 4095      记录数据（向上增长）
```

### 2.1 页头（24 字节，struct `>IBHHHiiIB`）

| 字段 | 大小 | 含义 |
|---|---|---|
| page_id | 4B | 页编号 |
| page_type | 1B | 0=FREE 1=DATA 2=META |
| slot_count | 2B | 槽数量 |
| free_start | 2B | 槽目录结束偏移（空闲起点） |
| data_end | 2B | 记录区结束偏移（空闲终点） |
| next_free_page | 4B | 空闲链表下一节点；DATA 根页复用为插入候选页 |
| next_data_page | 4B | 同表数据页链下一节点 |
| table_id | 4B | 数据页所属表，删除时 O(1) 归属校验 |
| reserved | 1B | 保留置零 |

### 2.2 槽目录（每项 5 字节，struct `>HHB`）

| 字段 | 大小 | 含义 |
|---|---|---|
| offset | 2B | 记录在页内偏移 |
| length | 2B | 记录字节长度 |
| flags | 1B | bit0 = `SLOT_DELETED` 已删除 |

### 2.3 页 0 元信息页（META）

页 0 固定为元信息页，页头之后依次：

- **元信息区**（偏移 24，16 字节，struct `>IIIi`）：`magic`（"MSQL"）→ `next_page_id` → `next_table_id` → `free_list_head`。
- **root_page 映射区**（偏移 40 起，每项 4 字节）：下标 = `table_id`，值 = 该表根页号，`0` 表示未分配。

设计要点：**根页不能靠 `root_page = table_id + 1` 纯函数推导**，因为数据页扩展会消耗页号，
所以把 `table_id → root_page` 显式持久化在页 0 的映射区。

## 3. 逐文件代码详解

### 3.1 `file_manager.py` —— FileManager

职责：屏蔽操作系统文件细节，提供**按偏移的定长读写**。

- `__init__(path)`：创建父目录；文件存在用 `r+b`、不存在用 `w+b`，均 `buffering=0`（无 Python 缓冲，写后可直接 `fsync`）。
- `read_at(offset, size)`：`seek` 后 `read`，返回 `bytes`；文件末尾可能短于 `size`，由调用方判断。
- `write_at(offset, data)`：`seek` 后循环 `write` 处理**部分写**（`memoryview` 追踪剩余字节），写不进就抛 `OSError`。
- `sync()`：`flush` + `os.fsync`，保证数据落到磁盘（提交前调用）。
- `close()`：关闭文件描述符。

答辩点：`buffering=0` 和 `write_at` 的循环写，是「提交可靠落盘」的地基。

### 3.2 `page.py` —— DiskPageManager

职责：页格式定义 + 页的分配/释放/读写 + 页 0 元信息维护。

**结构体与编解码（模块级）**
- `HEADER_STRUCT / SLOT_STRUCT / META_STRUCT`：用 `struct.Struct` 定义二进制布局。
- `PageHeader` / `StorageMeta`：`frozen dataclass`，不可变，字段清晰。
- `encode_* / decode_*`：页头/槽/元信息的打包与解包。

**DiskPageManager 关键方法**
- `__init__`：调 `_init_meta_if_needed`。空文件写全新页 0（`magic=MSQL, next_page_id=1, next_table_id=1, free_list_head=-1`）；非空但长度不足一页或 magic 不匹配，报 `CORRUPT_DATABASE` 拒绝覆盖。
- `allocate_page()`：空闲链表非空时取链表头（读页头 `next_free_page` 得到新链表头）；链表空时用 `next_page_id` 并递增。**先复用空闲页，避免文件无限增长。**
- `free_page(page_id)`：拒绝释放页 0；把该页清零并写成 FREE 页，页头 `next_free_page` 指向原链表头，再更新元信息链表头。
- `read_page / write_page`：按 `page_id * page_size` 定长读写，长度不符报 `IO_ERROR`。

答辩点：空闲页用**链表**管理（页头 `next_free_page` 串联），分配 O(1)、释放 O(1)。

### 3.3 `record.py` —— RowCodec 与 HeapStorage

#### RowCodec（记录编解码）

- `encode(schema, row)`：按列顺序编码，INT 用 `>q`（8 字节有符号大端），VARCHAR 用 `>H` 长度前缀 + UTF-8 字节。
- `decode(schema, data)`：按列顺序逆向解析。
- 关键校验：**bool 不得当 INT**（`isinstance(value, bool)` 先行排除）；INT 超 64 位、VARCHAR 超长、类型不符都抛 `TYPE_MISMATCH` / `INVALID_RECORD`。

答辩点：长度前缀按 **UTF-8 字节数**计，编解码两侧一致，中文字符串才能正确往返。

#### HeapStorage（堆存储，实现 RecordStorage 协议）

维护页 0 的元信息与 root_page 映射，并提供表级操作：

- `_get_root_page / _set_root_page(table_id)`：读/写页 0 映射区（下标 = table_id）。
- `_get_insert_hint / _set_insert_hint(table_id, page)`：**插入候选页指针**，复用 DATA 根页头 `next_free_page` 字段持久化。
- `_init_data_page(page_id, table_id)`：写一个空数据页（页头 `table_id` 标记归属）。
- `_compact_page(...)`：删除/插入时**整理页内字节**——把存活记录连续搬到页尾，已删除槽置 `offset=0,length=0,flags|SLOT_DELETED`，尾部空槽裁剪；不移动存活槽编号，保证 RecordId 稳定。
- `_insert_into_page(...)`：在 `data_end` 处写入记录字节，写槽目录；无空槽时追加槽、有删除槽时复用。

**表级操作**
- `create_table(schema)`：分配 `table_id`（用户表从 1 递增，`__catalog` 用 0），`allocate_page` 得到根页，写入映射区。
- `drop_table(schema)`：先完整校验数据页链（防链表损坏导致重复释放），再清根映射、`discard_page` 丢弃缓存、逐个 `free_page` 释放整表页。
- `insert(schema, row)`：从**插入候选页**开始找空间，填满前进、无空间则分配新页追加到链尾。
- `scan(schema)`：从根页沿 `next_data_page` 遍历，逐槽解码存活记录，返回 `StoredRecord`（含 RecordId）。
- `delete(schema, record_id)`：**直接按 `page_id` 定位**，校验页号范围、页类型、`table_id` 归属、槽有效后 `_compact_page` 删除；若目标页在候选页之前，回拨候选页使空洞可复用。
- `flush / close`：刷新缓冲池、关闭文件。

### 3.4 `buffer.py` —— PageBufferPool

职责：用 `OrderedDict` 统一实现 LRU 与 FIFO 两种替换策略。

- `get_page(page_id)`：命中 `hits++`，LRU 时 `move_to_end`；未命中 `misses++`，从磁盘读页，满则 `_evict_one`。
- `mark_dirty(page_id)`：把页加入脏页集合；页不在缓存时报错（防写回野指针）。
- `flush_page / flush_all`：脏页写回磁盘，`writebacks++`。
- `_evict_one()`：淘汰最左（LRU=最久未用，FIFO=最先进入）；**脏页先写回再淘汰**，写回失败保留脏页可重试。
- `stats()`：返回 `CacheStats(hits, misses, evictions)`；`writebacks` 记录成功写回次数；`replacement_log()` 记录每次替换事件。
- `discard_page(page_id)`：丢弃即将释放页的缓存与脏标记，**不写回**（数据已作废）。

答辩点：LRU 与 FIFO 的差异只在命中时是否 `move_to_end`，一个 `OrderedDict` 就统一了两种策略。

### 3.5 `journal.py` —— DatabaseLock 与 RollbackJournal

#### DatabaseLock（数据库级独占锁）

- 用操作系统文件锁：Windows `msvcrt.locking`、POSIX `fcntl.flock`。
- `acquire()` 带超时循环重试，超时抛 `DATABASE_BUSY`；`release()` 解锁。
- 整库独占锁保证同一时刻只有一个连接/进程能改数据。

#### RollbackJournal（写前回滚日志，完整前映像）

- `begin()`：把数据库**完整旧内容**写入临时日志（`magic` + 长度 + SHA256 摘要 + 数据），`fsync` 后原子发布为 `minisql.journal`。
- `commit()`：**先由调用者同步数据文件**，再追加 `COMMITTED` 提交标记并 `fsync`；清理日志失败不误报回滚。
- `rollback() / recover()`：校验日志（magic/长度/SHA256/提交标记），未提交则用前映像覆盖并截断数据库，再删日志。
- `durable_replace()`：Windows 用 `MoveFileExW(REPLACE_EXISTING|WRITE_THROUGH)`，POSIX 用 `os.replace` + 目录 `fsync`，保证日志原子发布。

答辩点：**先落数据、后写提交标记**；提交标记是「提交」的唯一判据，半标记按未提交回滚。

## 4. 关键算法与性能优化

1. **插入候选页指针（消除 O(N²)）**：原 `insert` 每次从根页线性扫到有空闲的尾页，复杂度 O(N²)。改为复用根页头 `next_free_page` 持久化「候选页」：插入从候选页开始、填满前进，删除使靠前页出现空洞时回拨。20,000 条插入从 101.9 s 降到 1.18 s。
2. **页头 table_id（消除删除 O(N·页数)）**：原 `delete` 为校验 RecordId 归属每次从根页遍历。改为页头持久化 `table_id`，删除直接按 `page_id` 定位并 O(1) 校验。
3. **页内整理不移动槽编号**：删除只重排字节、回收空间，存活槽编号不变，保证 RecordId 稳定、旧槽可复用。

## 5. 对外契约（跨模块接口）

存储层对外暴露三个 Protocol（定义在 `contracts/interfaces.py`）：

- `RecordStorage`：`create_table / drop_table / insert / scan / delete / flush / close` —— 执行引擎调用。
- `PageManager`：`allocate_page / free_page / read_page / write_page / close` —— 记录层调用。
- `BufferPool`：`get_page / mark_dirty / flush_page / flush_all / discard_page / stats / replacement_log` —— 记录层调用。

业务代码不依赖 `storage_format.md` 之外的具体字节布局，只通过上述协议交互。

## 7. 答辩讲解思路（口述要点）

建议按「分层 → 页格式 → 一条记录的生命周期 → 性能与可靠性」这条线讲：

1. **分层**：文件 → 页 → 记录 → 缓存 → 事务日志，各层职责单一。
2. **页格式**：4KB 页 = 24B 页头 + 5B×N 槽目录 + 记录区，槽向下长、记录向上长，中间是空闲。
3. **一条记录怎么落盘**：`HeapStorage.insert` → `RowCodec.encode` 成字节 → 找候选页 → 写记录区 + 写槽 → `mark_dirty` → `flush` 时经 `FileManager.write_at` 落盘。
4. **为什么快**：插入候选页指针、页头 table_id，让插入和删除都近似线性。
5. **为什么可靠**：LRU/FIFO 脏页先写回；事务先落数据、后写提交标记；崩溃后用前映像回滚。
6. **难点**：根页显式映射（不能纯函数推导）、中文字符串 UTF-8 字节边界、O(N²) 的定位与修复。
