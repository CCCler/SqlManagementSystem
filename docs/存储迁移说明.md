# 存储格式迁移说明（V1 → V2，成员二）

本文说明 MiniSQL 旧库（V1）升级到新格式（V2）的工具、保证与操作步骤。磁盘布局细节见
[存储格式设计](storage_format.md) 第 6、8、9、10 节。

## 1. 何时需要迁移

- V1：仅 INT/VARCHAR 列、不支持 NULL，历史文件页 0 的 `reserved` 字节为 `0`。
- V2：支持 NULL 与 BOOL/DECIMAL/DATE/TIME/TIMESTAMP；新库默认写 V2。
- **未经确认不转换业务目录**：迁移只在显式执行 `--apply` 时发生；缺省为预演，只读不改。
- V2 库不需要迁移；再次调用为空操作。

## 2. 命令行用法

```bash
# 预演：统计将迁移的表与行数，不改动任何文件
PYTHONPATH=src python -m minisql.cli.migrate <数据库目录>

# 执行迁移（默认先备份原文件为 minisql.db.v1.bak）
PYTHONPATH=src python -m minisql.cli.migrate <数据库目录> --apply

# 执行迁移且不备份（仅在已有外部备份时使用）
PYTHONPATH=src python -m minisql.cli.migrate <数据库目录> --apply --no-backup
```

`<数据库目录>` 是包含 `minisql.db` 的目录（与 `open_database(path)` 的 path 一致）。
退出码：`0` 成功（含无需迁移），`1` 失败（错误码与原因输出到 stderr）。

## 3. 迁移做了什么

1. 识别版本；已是 V2 则直接返回。
2. 持数据库级锁，复核版本，拒绝存在未处理事务日志的库。
3. 备份原文件：`minisql.db.v1.bak`（可 `--no-backup` 关闭）。
4. 在临时文件 `minisql.db.migrating` 中按 V2 重建：先建 `__catalog`，再按原
   `table_id` 顺序逐表复制记录并重新登记目录。
5. `fsync` 临时文件后用 `durable_replace` 原子替换 `minisql.db`，并同步目录项。

## 4. 保证

| 保证 | 说明 |
|---|---|
| 不自动迁移 | 缺省只预演；业务目录仅在 `--apply` 时被改动 |
| 原子替换 | 临时文件写透后整文件替换，不存在“迁移到一半”的可见状态 |
| 中断安全 | 替换前原库完好；重跑自动清理残留临时文件并重新迁移 |
| 备份 | 默认保留迁移前完整副本 `minisql.db.v1.bak` |
| 幂等 | 已迁移库再次调用直接返回“无需迁移”，不改动文件 |
| table_id 保留 | 原表编号原样复制（允许编号空洞），避免上层元数据引用失效 |
| 数据保真 | 逐行读取 + 重新编码，记录内容与顺序不变；目录由规范路径重新登记 |

## 5. 拒绝迁移的情形

| 情形 | 错误码 | 处理 |
|---|---|---|
| 目录内不存在 `minisql.db` | `IO_ERROR` | 确认目录正确 |
| 存在未处理的事务日志 `minisql.journal` | `RECOVERY_REQUIRED` | 先正常 `open_database` 打开一次完成恢复，再迁移 |
| 数据库被其他连接占用 | `DATABASE_BUSY` | 关闭其他连接后重试 |
| 数据库魔数无效或文件不完整 | `CORRUPT_DATABASE` | 保留文件排查，不覆盖、不清空 |

拒绝时原文件保持不变。

## 6. 失败恢复步骤

1. 若迁移中断，原 `minisql.db` 仍是迁移前的 V1；残留的 `minisql.db.migrating`
   可手动删除，也可直接重跑命令（工具会自行清理）。
2. 确认目标结果无误后，可删除 `minisql.db.v1.bak` 释放空间。
3. 若迁移结果异常，用备份回退：`mv minisql.db.v1.bak minisql.db`（先关闭所有连接）。

## 7. 已知限制与待办

- 迁移工具目前只处理 **V1 → V2**；未来出现 V3 时需要扩展 `_rebuild` 的编码选择，
  但“备份 + 临时文件 + 原子替换”的框架可复用。
- `__catalog` 已修复 DECIMAL 参数保存：类型字段写入 `DECIMAL(p,s)`，重开恢复 precision/scale，系统表列数和页格式不变。旧裸类型名继续可读。
  修复前已丢失的参数不能从裸 `DECIMAL` 名称推断恢复；需依据原始建表定义另行处理。新参数描述需使用本修复版本读取，旧版本不识别 `DECIMAL(p,s)`。本次 V1 库不含新类型，因此迁移不受影响。
- 迁移触发入口现为独立 CLI（避免占用其他成员接口）；是否需要由 GUI 或引擎在打开
  旧库时提示迁移，由成员三确认后再接入。

## 8. 实测

`tests/storage/test_migrate.py` 共 10 项：版本识别、预演不改文件、执行后数据与目录
恢复（含真实引擎 `SELECT`）、备份字节一致、幂等、`table_id` 保留（含编号空洞）、
待处理日志拒绝、缺失库拒绝、损坏输入拒绝、子进程迁移中断后原库完好且可重跑。
