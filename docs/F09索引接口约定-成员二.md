## 二、BTreeIndex 接口契约

```python
from minisql.storage.index import BTreeIndex

# 新建索引：分配根页并落盘空叶子；返回的实例维护内存态 root_page。
index = BTreeIndex.create(pages, buffer, columns, table_id=0)

# 重新打开：root_page 由调用方从持久化元数据读出后传入。
index = BTreeIndex(pages, buffer, columns, root_page, table_id=0)

index.insert(values, record_id)          # values 为列键 tuple，record_id 为 RecordId
index.delete(values, record_id)          # 删除一个 (键, rid) 条目
index.lookup(values) -> list[RecordId]   # 等值查询，返回该键下全部 rid（按键内 slot 序）
index.range_scan(lo, hi, lo_inclusive=True, hi_inclusive=True) -> list[RecordId]
index.scan_all() -> list[RecordId]       # 按键有序的全量 rid
index.drop()                             # 释放整棵索引树的所有页（DROP INDEX 用），调用后本实例不可再用
index.root_page                          # 公开属性：索引根页号（调用方负责持久化）
```

- `columns` 是 `tuple[ColumnSchema, ...]`，来自表的列定义；联合索引传多列，顺序即键顺序。
- `pages` / `buffer` 与 `HeapStorage` 共用同一 `DiskPageManager` / `PageBufferPool` 实例。
- 索引页与数据页写入同一个 `minisql.db` 文件，事务日志为整文件前映像，因此**索引页自动随数据页一起提交、回滚和崩溃恢复**，无需额外协议（已由 `test_index_and_data_recover_together` 验证）。

## 三、键编码语义（成员一/三必须一致）

- **NULL 排在所有非 NULL 值之前**；`lookup((None,))` 只命中 NULL 键，不与任何具体值混淆。
- 联合键按列顺序做字典序比较：第一列优先，等同才比较第二列，支持**最左前缀**范围扫描。
- 重复键允许存在，`lookup` 返回全部匹配 rid；唯一性约束由上层（成员三）在写入前检查。
- 范围边界 `lo` / `hi` 均可为 `None`（无下/上界），`lo_inclusive` / `hi_inclusive` 控制开闭。
- 键编码保序：索引扫描结果天然有序，无需在索引层排序；与全表扫描 + ORDER BY 的结果一致。

## 四、成员三接入清单（需协调）

1. **索引元数据持久化（root_page）**：成员三提案的 `__indexes` 系统表结构
   （`index_id, index_name, table_name, unique_flag, column_index, column_name`）**缺少 root_page 列**。
   索引根页号必须持久化才能重开恢复，建议在 `__indexes` 增加 `root_page INT` 列，登记时保存
   `index.root_page`；重开时据此构造 `BTreeIndex(pages, buffer, columns, root_page, table_id)`。
   该列由成员三在 Catalog 层维护，成员二不新增页 0 映射区。

2. **存量索引构建**：`CREATE INDEX` 时遍历 `HeapStorage.scan(schema)` 得到 `(row, record_id)`，
   对每条记录调用 `index.insert(键值, record_id)`，完成后把 `index.root_page` 写入 `__indexes` 并 `flush`。
   构建与建索引登记应处于同一事务，失败整体回滚（索引页随数据页恢复，见上）。

3. **同步维护 INSERT/UPDATE/DELETE**：数据写入成功后，对同一事务内的索引做对应维护——
   - INSERT：`index.insert(键, rid)`；
   - DELETE：`index.delete(键, rid)`；
   - UPDATE：若索引列未变则无需操作；若变，等价于 `index.delete(旧键, 旧rid)` + `index.insert(新键, 新rid)`。
   `rid` 以 `HeapStorage.insert/scan` 返回的 `RecordId` 为准（UPDATE 替换记录后 rid 可能改变，见接口约定）。

4. **索引查询接入**：等值/范围条件命中索引时用 `lookup` / `range_scan` 得到 rid 列表，
   再按 rid 从数据页取记录；结果顺序与全表扫描一致。访问路径选择与 EXPLAIN 由成员一负责。

5. **唯一索引**：唯一性在成员三写入前检查——`if index.lookup(键): 拒绝（DUPLICATE_KEY）`。
   B+ 树存储层不区分唯一/普通索引（两者页布局完全相同），`unique_flag` 仅由 Catalog 记录。

## 六、性能证据（真实测量口径）

脚本 `python -m minisql.cli.benchmark_index [N]`，只测量存储层 BTreeIndex 与 HeapStorage.scan，
不含 SQL 编译与事务日志。指标为**磁盘页访问次数**（buffer misses），冷缓存每次重建缓冲池，热缓存同一缓冲池连续访问：

| 数据规模 | 索引等值(冷,miss/次) | 全表扫描(冷,miss/次) | 索引等值(热,miss/次) | 全表扫描(热,miss/次) |
|---|---|---|---|---|
| 10000 | 2.0 | 35.0 | 0.43 | 0.17 |
| 50000 | 3.0 | 173.0 | 0.95 | 173.0 |

- 冷缓存等值查找：索引磁盘访问 ≈ B+ 树高（2~3 次），全表扫描 ≈ 数据页数（35~173 次），差距随规模扩大。
- 热缓存下 N=50000 全表扫描数据页（173）超出缓存容量 64，仍每次全缺页；索引等值只访问路径上的 2~3 页，增量访问近 0。
- 数据规模、缓存容量、随机 key 分布（seed=42）与测量口径均可复现；耗时受环境噪声影响，未作为结论依据。
