# 存储格式设计（成员二）

本文档记录存储层磁盘格式，供成员三联调时查阅。业务代码不应依赖本文档之外的具体字节布局，
只通过 `RecordStorage` / `PageManager` 协议交互。

## 1. 页格式

- 默认页大小 `PAGE_SIZE = 4096` 字节。
- 每页分为三部分：页头、槽目录、记录数据区。
- 槽目录从页头之后向下增长，记录数据从页尾向上增长，两者之间为空闲空间。

```
偏移 0          页头（24 字节）
偏移 24         槽目录（每项 5 字节，向下增长）
                ...
                ↓ 空闲空间 ↑
                ...
偏移 4095       记录数据（向上增长）
```

### 1.1 页头（24 字节）

struct 格式 `>IBHHHiiIB`：

| 字段 | 大小 | 说明 |
|---|---|---|
| page_id | 4B | 页编号，无符号 |
| page_type | 1B | 0=FREE 1=DATA 2=META |
| slot_count | 2B | 当前槽数量 |
| free_start | 2B | 槽目录结束偏移（空闲空间起点） |
| data_end | 2B | 记录数据区结束偏移（空闲空间终点） |
| next_free_page | 4B | 空闲页链表下一节点，-1 表示空/尾；DATA 根页复用为插入候选页 |
| next_data_page | 4B | 同表数据页链表下一节点，-1 表示尾 |
| table_id | 4B | 数据页所属表编号，删除时 O(1) 归属校验；META/FREE 页为 0 |
| reserved | 1B | 页 0 承载格式版本号（V1=1、V2=2；历史文件为 0，读取时归一化为 V1），其余页置零 |

### 1.2 槽目录（每项 5 字节）

struct 格式 `>HHB`：

| 字段 | 大小 | 说明 |
|---|---|---|
| offset | 2B | 记录在页内的偏移 |
| length | 2B | 记录字节长度 |
| flags | 1B | bit0=已删除（`SLOT_DELETED`） |

## 2. 页类型

| 类型 | 值 | 说明 |
|---|---|---|
| FREE | 0 | 空闲页，页头 `next_free_page` 串联空闲链表 |
| DATA | 1 | 数据页，含槽目录与记录，`next_data_page` 串联同表数据页 |
| META | 2 | 元信息页，仅页 0 |
| INDEX_LEAF | 3 | B+ 树叶子节点，见第 8 节 |
| INDEX_INTERNAL | 4 | B+ 树内部节点，见第 8 节 |

## 3. 页 0 元信息页

页 0 固定为元信息页，页头之后依次为元信息区与 root_page 映射区。

### 3.1 元信息区（偏移 24，共 16 字节）

struct 格式 `>IIIi`：

| 字段 | 大小 | 说明 |
|---|---|---|
| magic | 4B | 魔数 `0x4D53514C`（"MSQL"），用于识别有效文件 |
| next_page_id | 4B | 下一个可分配的页编号 |
| next_table_id | 4B | 下一个可分配的表编号（HeapStorage 维护） |
| free_list_head | 4B | 空闲页链表头，-1 表示空 |

### 3.2 root_page 映射区（偏移 40 起，每项 4 字节）

- 下标 = table_id，值 = 该表根页号；`0` 表示未分配。
- struct 格式 `>I`。
- `table_id=0` 对应 `__catalog`，用户表从 1 开始，下标连续。
- 最大可映射表数约 `(4096 - 40) / 4 = 1014`。

仅空文件由 `DiskPageManager` 自动初始化为
`magic=MSQL, next_page_id=1, next_table_id=1, free_list_head=-1`，映射区全 0。非空但不足一页或 magic 不匹配时返回 CORRUPT_DATABASE，不覆盖原文件。

## 4. 空闲页管理

- 采用空闲页链表：空闲页的页头 `next_free_page` 指向下一空闲页。
- 分配时从链表头取页；链表空时分配 `next_page_id` 并递增。
- 释放时把页插入链表头，并清零页内容。
- 页 0 不允许释放。

## 5. table_id 与根页映射

- `table_id=0` 保留给系统表 `__catalog`，用户表从 1 开始，由 `next_table_id` 递增分配。
- 每张表的根页（root_page）由 `allocate_page` 独立分配，页号不要求与 table_id 对齐
  （数据页扩展会消耗页号，因此不能用纯函数推导根页）。
- `table_id -> root_page` 的映射显式持久化在页 0 的 root_page 映射区（第 3.2 节）。
- 表根页作为该表数据页链表的入口，数据页通过页头 `next_data_page` 串联。

## 6. 记录编码（RowCodec）

记录编码按格式版本分派：`RowCodec(format_version)`。

- **V1（旧格式）**：仅 INT/VARCHAR，每个值无前缀。
- **V2（当前格式）**：每个值前有 1 字节可空标记（`0x00` 表示有值，`0x01` 表示 NULL），
  支持全部类型与 NULL。

各类型编码：

| 类型 | 编码 |
|---|---|
| INT | 8 字节有符号大端 `>q`，范围 `[-2^63, 2^63-1]` |
| VARCHAR | 2 字节长度前缀 `>H`（按 UTF-8 字节计）+ UTF-8 字节 |
| BOOL | 1 字节 `>?`（0/1） |
| DECIMAL | 2 字节长度前缀 + 十进制文本 UTF-8（`str(value)`），非有限值拒绝 |
| DATE | 4 字节有符号大端 `>i`，距 1970-01-01 的天数（可为负） |
| TIME | 8 字节有符号大端 `>q`，自午夜起的微秒数 |
| TIMESTAMP | 8 字节有符号大端 `>q`，距 1970-01-01 00:00:00 的微秒数（可为负） |

- bool 不得作为 INT 存储，INT 也不能接收 bool（尽管 bool 是 int 的子类）。
- 记录不跨页；单条记录编码后的最大长度受页容量约束：

```
记录最大长度 = 4096 - 页头(24) - 槽(5) = 4067 字节
```

超出该上限在记录层（HeapStorage）报 `INVALID_RECORD` 存储错误。
- V1 编解码器遇到新类型或显式 NULL 报 `TYPE_MISMATCH`（提示需要格式版本 2），
  不静默降级，保证旧库只读旧格式。

## 7. 持久化与恢复

- 页分配信息（`next_page_id`、`free_list_head`）持久化在页 0 元信息区（DiskPageManager 维护）。
- `next_table_id` 与 root_page 映射区持久化在页 0（HeapStorage 维护）。
- 正常关闭后重新打开：页分配器、空闲链表、表根页映射与记录均完整恢复。
- DELETE 会整理页内记录字节，回收负载空间；存活槽编号不变，中间删除槽置为 offset=0、length=0、flags 包含 SLOT_DELETED，尾部空槽移除。
- INSERT 优先复用删除槽，无空槽时才追加槽；不承诺按插入时间扫描。全部记录删除后，slot_count=0、free_start=24、data_end=4096，页恢复完整可用容量。
- 旧文件中保留原 offset/length 的删除槽仍可读取，页再次插入或删除时统一整理，无需迁移格式。
- 存活 RecordId 不变，已删除 RecordId 不得继续使用，因为槽可能重用。
- 空页不从表页链摘除，供同表复用，不主动缩小文件；DROP TABLE 释放整表页到全局空闲链表。

数据库页格式保持兼容。事务额外使用 minisql.journal 完整前映像日志和 minisql.lock 操作系统锁，恢复同时覆盖元信息、空闲链表、Catalog 与数据页。具体格式及同步顺序见 [事务与恢复](事务与恢复.md)。底层存储接口独立使用时不提供事务保证。

旧版数据页未保存 table_id（保留字段全零）。删除此类记录时先从目标表根页验证页链归属，成功删除时补写该用户页的 table_id；不将 0 直接当作任意表或系统表归属。验证包含环检测，遍历后重新获取缓存引用，兼容小容量缓存。补写属于原删除事务，回滚与崩溃恢复同样撤销；已标记的用户页仍按页头直接校验。

## 8. 索引页格式（B+ 树）

索引页复用同一套 4096 字节页与 24 字节页头，页类型为 `INDEX_LEAF=3` / `INDEX_INTERNAL=4`。
页头部分字段被复用：

| 页头字段 | 索引页含义 |
|---|---|
| slot_count | 节点条目数 |
| next_free_page | 内部节点的最左子页 `child0`（叶子为 NO_PAGE） |
| next_data_page | 叶子节点的后继叶子 `next_leaf`（内部节点为 NO_PAGE） |
| table_id | 索引所属表编号 |

节点体（页头之后）：

- 内部节点：先 4 字节 `child0`，随后每个条目为 `2 字节长度前缀 + 全键`，全键 = 列键 + 4 字节子页指针。
- 叶子节点：每个条目为 `2 字节长度前缀 + 全键`，全键 = 列键 + 8 字节 rid（page_id + slot_id）。

容量与平衡：

- 节点体上限 `MAX_BODY_SIZE = 4096 - 24 = 4072` 字节，超出即分裂；非根节点下溢阈值
  `MIN_BODY_SIZE = 2036`，下溢时先借用后合并，根塌缩后释放空页。
- 重复列值也有唯一全键（列键 + rid），因此不需要额外的重复键处理分支。
- 页回收复用 `BufferPool.discard_page` + `PageManager.free_page` 回到全局空闲链表。

键编码（KeyCodec）：字节字典序等价于 SQL 值排序，自定界。

- NULL 编码为单字节 `0x00`，排在所有非 NULL 值之前；非 NULL 值以 `0x01` 开头。
- INT/DATE/TIMESTAMP 做符号翻转后按无符号比较；TIME 恒非负。
- VARCHAR 以 `0x00 0x00` 结尾，字节 `0x00` 转义为 `0x00 0xff`，保持 UTF-8 字典序。
- DECIMAL 编码为“符号 + 整数位数 k + 数字串”，负数补码反转。
- 联合键按列顺序比较，支持最左前缀范围扫描。索引扫描结果天然按键有序。

## 9. 表结构重写与物理结构替换

`HeapStorage.rewrite_table(schema, new_schema, transform)` 提供 F06 所需的存储层能力，
不解析 SQL、不更新 Catalog（由上层负责）：

1. 遍历旧表存活记录，逐条调用 `transform(row)`；返回新行则编码，返回 `None` 则丢弃该行。
   全部转换与编码在改动物理结构之前完成。
2. 在全新页链上写入编码结果（不触碰 `table_id → root_page` 映射）。
3. 原子切换该表的 root_page 映射，刷新插入候选页。
4. 释放旧页链（`discard_page` + `free_page`）。

失败语义：第 1 步的类型/容量错误、`transform` 抛出的异常都不改动旧结构与旧数据；
第 3 步之后释放旧页失败只泄漏旧页，不影响已切换的新数据。崩溃安全由调用方的事务
（整文件前映像日志）覆盖，存储接口独立使用时不提供事务保证。

该能力可用于增列/删列/重命名/改类型等结构变更的数据重写；旧页链会回到空闲链表，
后续插入可复用，文件不主动缩小。

## 10. 格式版本与迁移

- 格式版本号存放于页 0 页头 `reserved` 字节：`1` = V1（旧格式），`2` = V2（当前格式）；
  历史文件该字节为 `0`，读取时归一化为 V1，保证旧库可读、不被自动改写。
- 新文件由 `DiskPageManager` 初始化时写入当前版本（V2）。
- V1→V2 迁移工具为 `minisql.engine.migrate.migrate`，命令行入口
  `python -m minisql.cli.migrate <目录> [--apply] [--no-backup]`（默认只预演）。
- 迁移流程：识别版本 → 备份原文件 → 在临时文件 `minisql.db.migrating` 内按 V2
  重建全部用户表与 `__catalog` → fsync → `durable_replace` 原子替换 `minisql.db`。
- 迁移保留原 `table_id`（直接设置目标库 `next_table_id`，允许编号空洞），避免上层
  元数据引用失效。
- 中断安全：临时文件未替换前原库完好；重跑会自动清理残留临时文件并重新迁移，
  已迁移（V2）的库再次调用为空操作。存在未处理事务日志时拒绝迁移。
- 详细操作、保证与限制见 [存储迁移说明](存储迁移说明.md)。
