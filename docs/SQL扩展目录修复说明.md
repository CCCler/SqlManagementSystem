本次基于 ad7cee5 修复已复现问题，未提交或推送，也未操作业务数据库。

## 已修复

- 旧六列 `__indexes` 的有记录数据库可重新打开；缺失 root_page 恢复为 None，读取、删除及不带根页的登记继续兼容。不猜测 B+ 树根页。旧布局登记非空根页时报 CATALOG_UPGRADE_REQUIRED，需要后续显式升级工具；本次不自动重写业务目录。
- 新约束将列名顺序和被引用列清单共同保存在现有 reference_columns 文本字段中，使用带 version 的 JSON 描述，不改变系统表布局。恢复不再按物理列序号排序；空槽复用也不改变复合键顺序。旧列表形式仍可读取，按旧行扫描顺序恢复；历史上未保存的顺序无法凭空推断。
- 视图列类型复用普通表的 DECIMAL(p,s) 编解码，重开保留 precision/scale；先校验全部类型再登记。旧裸 DECIMAL 保持兼容，已丢失参数不能自动恢复。
- SQL 编译入口拒绝所有 `__` 前缀的系统表访问，覆盖旧查询、别名、子查询、EXPLAIN 和通过视图展开的访问，也禁止用 SQL 创建内部名称。错误为带位置的 PROTECTED_TABLE，GUI 不生成结果或包含敏感字段的编译记录。内部 Catalog 查询仍供迁移、引导和账户存储使用。
- 数据库把真实对象目录中的视图定义适配给编译器，持久化视图可以正确识别、展开并在 EXPLAIN 中展示，写视图明确拒绝。

## 仍需接入的功能

视图识别修复不等于新查询算子完成。普通视图 SELECT 仍返回 FEATURE_NOT_EXECUTABLE，替代错误的 UNKNOWN_TABLE；相关子查询、JOIN、聚合等计划仍由执行保护拦截。未新增实际视图查询执行、统一用户鉴权或登录界面；本次账户修复是阻断内部信息暴露，不宣称权限系统已全部接通。
