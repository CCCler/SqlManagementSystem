# 教师演示方案（MiniSQL 答辩演示脚本）

建议总时长 15～20 分钟。所有演示在项目根目录、虚拟环境内执行；
每条命令都给出了预期输出和讲解要点。演示数据目录统一使用 `data/demo`，
首次演示前删除该目录保证干净状态。

## 〇、演示前准备（5 分钟，演示前完成）

```powershell
# 1. 进入项目根目录，确认虚拟环境
.\.venv\Scripts\python.exe -m pytest -q        # 预期 603 passed, 0 skipped

# 2. 终端设为 UTF-8，避免中文乱码（Windows PowerShell 需要）
chcp 65001

# 3. 清理演示数据目录（若存在）
Remove-Item -Recurse -Force .\data\demo -ErrorAction SilentlyContinue
```

## 一、开场（1 分钟）

**讲**：MiniSQL 是课程《大型平台软件设计实习》的完整自研数据库实现，
覆盖 SQL → Token → AST → 语义检查 → 计划 → 执行器 → 缓存/页 → 磁盘 全链路。
仅用 Python 3.11+ 标准库，未使用 SQLite 等现成数据库。三位成员分别负责
编译器、页式存储、执行引擎与集成，全套 603 项测试通过。

## 二、核心链路演示（CLI 文件模式，3 分钟）

```powershell
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\demo --file .\examples\core.sql
```

预期输出（逐行讲解）：

```
表 student 已创建          ← CREATE TABLE：物理页先分配，再登记目录
已插入 1 行                ← INSERT ×2
id | name
---+------
1  | Alice                 ← SELECT ... WHERE age > 18：过滤正确
已删除 1 行                ← DELETE ... WHERE id = 1：RecordId 全程保留
id | name
---+-----
2  | Bob                   ← 删除后再查：只剩 Bob
```

**接着演示持久化**（重启不是同进程，是全新进程）：

```powershell
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\demo --file .\examples\verify.sql
```

**讲**：关掉进程重开，数据仍在——表数据与目录都经 4KB 页系统持久化。

## 三、错误诊断（2 分钟）

进入交互模式（交互模式出错后会话继续，可连续演示多条错误）：

```powershell
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\demo
```

```sql
SELECT score FROM student;                                    -- 未知列
INSERT INTO student(id,name,age) VALUES ('Alice',1,20);        -- 类型不匹配
SELECT name FROM student WHERE age > 18 AND;                   -- 语法错误
SELECT name FROM student WHERE name = 'unterminated;           -- 字符串未闭合
```

**讲**：每条错误都带阶段、错误码和精确行列位置（如
`semantic:UNKNOWN_COLUMN at 1:8`）；出错后会话继续、之前成功语句保持有效。
文件模式遇错则停止后续语句并返回退出码 1（`examples/errors.sql` 汇集了
六类错误用例，各自在独立环境中验证，对应 6 项集成测试）。

## 四、事务与并发（3 分钟）

开**两个终端**，都指向同一数据目录，演示整库独占锁：

终端 A（交互模式）：

```powershell
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\demo
```

```sql
BEGIN;
DELETE FROM student WHERE id = 2;
INSERT INTO student(id,name,age) VALUES (3,'Carol',21);
```

此时**先不提交**，切到终端 B 执行：

```powershell
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\demo --lock-timeout 0
```

```sql
SELECT * FROM student;
```

终端 B 报 `DATABASE_BUSY`（锁等待超时）。回到终端 A：

```sql
ROLLBACK;
SELECT id,name FROM student;
```

**讲**：回滚后 Bob 仍在、Carol 消失；事务含 DDL（CREATE/DROP TABLE）同样
可回滚；整库前映像日志保证异常退出后可恢复（`minisql.journal` 文件，
正常关闭后自动清理）。

## 五、扩展特性（3 分钟）

在交互模式依次执行并讲解：

```sql
EXPLAIN SELECT * FROM student WHERE 1=2;   -- 计划树：Project → EmptyScan（恒假优化，不扫描）
SELECT * FROM student WHERE TRUE;          -- 恒真：Filter 消除后照常返回
SELECT * FROM student ORDER BY age DESC LIMIT 2 OFFSET 1;   -- 排序 + 分页
SELECT DISTINCT name FROM student;         -- 去重
DROP TABLE student;                        -- 删表：整表页链释放供复用，受事务保护
```

编译全阶段展示（Token→AST→语义→优化前后计划，JSON Lines）：

```powershell
.\.venv\Scripts\python.exe -m minisql --data-dir .\data\demo --file .\examples\trace.sql --trace
```

## 六、图形工作台（2 分钟）

```powershell
start_gui.cmd
```

浏览器自动打开本地界面：SQL 高亮编辑、分页结果表、表结构与数据浏览、
事务操作、Token/AST/执行计划分析、真实缓存统计。**讲**：GUI 与 CLI 走同一
引擎入口，展示的编译信息来自实际调用，不会重复执行 SQL。

## 七、查询统计与规模验证（1 分钟）

```powershell
.\.venv\Scripts\python.exe examples\benchmark.py --sizes 100 1000 10000
```

**讲**：真实页存储上扫描行数、页访问（冷/热缓存命中缺失）、耗时与事务边界
对比；扫描行恒等于全表行数、执行器耗时线性增长、热缓存缺失归零；
"用户表扫描减少"与"事务整库日志开销"是两本账。

## 八、收尾：架构与测试证据（2 分钟）

- 分层调用链：`CLI/GUI → Database → SQLCompiler → PlanExecutor → HeapStorage
  → PageBufferPool → DiskPageManager → FileManager → 磁盘`
- 关键设计点可挑 2～3 个讲：RecordId 保留策略（删除不经过投影）、
  系统目录绕过编译恢复、事务装配（锁 + 前映像日志 + 提交标记）、
  恒真/恒假计划优化与语义检查先行
- 测试证据：`pytest` 603 项通过、零跳过；Fuzz 固定种子 120 变异案例；
  异常 I/O 与资源释放专项；子进程强退恢复

## 九、答疑预案

| 可能的提问 | 回答要点 |
|---|---|
| 为什么不用 SQLite？ | 课程要求自研全链路，SQLite 会替代页式存储与执行器的全部工作 |
| 并发怎么保证？ | 整库独占锁 + 写前回滚日志，串行事务；首版明确不做行锁/MVCC |
| 性能如何？ | 给出 benchmark 实测数字；说明批量加载应显式事务内逐条执行（O(N²) 来自文件级位置保留的架构约定） |
| 还不支持什么？ | UPDATE/JOIN/GROUP BY/索引（首版边界，扩展计划已制定） |
| 表已存在报错？ | 换 `--data-dir` 新目录即可，数据目录与代码无关 |

（core.sql → 重启持久化 → 事务回滚 → 错误诊断 → 删表重建）自带预期断言，
任何一步失败会立即报错，适合作为开场或备用。
