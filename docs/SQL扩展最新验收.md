## 拉取时确认的问题（后续修复见下节）

1. **高优先级：嵌套子查询鉴权遗漏。** 创建 t 和 secret，普通用户只有 t 的 SELECT 权限；直接 SELECT id FROM secret 被拒绝，但 `SELECT id FROM t WHERE id=1 AND EXISTS(SELECT id FROM secret);` 返回数据。执行器权限遍历未递归覆盖嵌套表达式。需由成员三补齐遍历及授权回归。
2. **数据库级授权未对齐。** 管理员执行 `GRANT CREATE TABLE ON DATABASE main TO alice;`，编译成功但执行报 `UNKNOWN_OBJECT_KIND: database`。授权存储及 DDL 鉴权对象范围需要对齐。
3. **SQL 建视图丢失 DECIMAL 参数。** `CREATE TABLE d(x DECIMAL(10,2)); CREATE VIEW v AS SELECT x FROM d;` 后，目录中的视图列 precision/scale 均为 None。目录编解码修复已保留，但执行器创建 ColumnSchema 时未传入参数。
4. **ALTER USER 尚未实现执行。** 新版测试明确期待 FEATURE_NOT_EXECUTABLE，不能将修改密码列为已完成。
5. **展示状态过时。** 可执行 JOIN 的 EXPLAIN 仍展示“执行待接入”；应按实际能力更新说明。部分历史文档也仍保留旧阶段描述。

上述记录描述首次拉取时的状态；后续修复如下。全套测试通过表示当前已有断言通过，并不抵消上述独立探测结果，也不代表性能、全部权限边界及全部迁移场景已验收。
